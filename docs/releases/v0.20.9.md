# Clumsies v0.20.9

The App and daemon now preserve open-document Bases and retry unsaved edits
while reclaiming unused local history and bounded diagnostic caches.

## Install and update

| Platform | Download | Notes |
| --- | --- | --- |
| macOS | `Clumsies-0.20.9-macos-arm64.dmg` | macOS 14 or later on Apple Silicon. Install the whole App, then run its Install CLI.command if needed. Existing installations can use Check for Updates. |
| Linux CLI | `clumsies-cli-0.20.9-linux-x86_64.tar.gz` | Extract and run `./install.sh`. Reopen the terminal. Ubuntu 24.04 x86-64 or compatible glibc systems. |
| Windows CLI | `clumsies-cli-0.20.9-windows-x86_64-Setup.exe` | Current-user installation with PATH setup. Reopen the terminal. Windows x64. |

Upgrade the CLI and daemon together; macOS obtains both from the App bundle.
Installation preserves credentials, project bindings, Drafts and existing
history. Verify the published SHA-256 files before installation.

The macOS App is ad-hoc signed and not notarized by Apple; manual installation
may require Open Anyway in System Settings. Windows installers are unsigned.

## Changes since v0.20.8

- Open documents retain their actual historical Base with acknowledged OS
  file leases. Collection also retains current references and every Base
  required by open or submitted Drafts or unsynchronized operations. After
  readers close, unreachable central history and derived generations can
  be reclaimed without rewriting historical payloads.
- Failed saves retain the edited text for retry and block application exit
  or workspace transitions until local persistence succeeds. Late results
  from an earlier account or project cannot replace the active workspace.
- Local Draft writes use full SQLite WAL durability. Retrieval text is
  shared instead of duplicated; ordinary diagnostic history, response
  caches, work queues, logs and avatar caches have bounded retention.
  Evaluation evidence and its source snapshots remain protected.
- SQLite page and WAL reclamation releases unused space. Retired runtime
  and native cache code has been removed from active paths.
- Client performance and synchronization diagnostics include local timing
  and convergence information.
- Concurrent requests preserve the sign-in error when the same session
  expires. Requests from a replaced account remain isolated, and denied
  reads cannot return an older fallback response.
- Windows CLI editor and pager commands preserve quoted arguments and
  generated file paths, including spaces and shell-special characters.

## Compatibility and migration

The local schema advances from 42 to 44; IPC revision remains 1. Migration
preserves operation order and raw JSON, immutable Commit/Tree/Blob bytes,
and historical Draft Bases. Older derived-cache resets preserve central
history; schema-18 evaluation records retain their original fields in
retired tables while the current evidence projection is deduplicated.

If a schema-13 database contains unmappable metaprompt Drafts or operations,
upgrade refuses before changing its schema or rows. Export those records
through a compatible older client before retrying the upgrade.

## Rollback

Keep a backup before upgrading. A schema-44-compatible daemon can reopen the
upgraded database. A daemon supporting only schema 42 cannot: export later
edits first, then restore the pre-upgrade database with that older App.
Do not replace the daemon alone while leaving mismatched App components.
