# Clumsies v0.20.7

A more readable CLI for projects, Memory and Reviews, with shell installation
and a fix for synchronization blocked by old terminal Drafts. The native
macOS App remains supported; Windows and Linux ship CLI/daemon packages only.

## Install and update

| Platform | Download | Notes |
| --- | --- | --- |
| macOS | `Clumsies-0.20.7-macos-arm64.dmg` | macOS 14 or later on Apple Silicon. Install the App, then run the bundled Install CLI.command to make `clumsies` available in the terminal. Existing installations can use Check for Updates. |
| Linux CLI | `clumsies-cli-0.20.7-linux-x86_64.tar.gz` | Extract and run `./install.sh`. The installer configures bash/zsh PATH. Reopen the terminal. Ubuntu 24.04 x86-64 or compatible glibc systems. |
| Windows CLI | `clumsies-cli-0.20.7-windows-x86_64-Setup.exe` | Current-user installation with PATH setup; no administrator permission required. Reopen the terminal. Windows x64. |

The matching Windows ZIP supports portable use and includes `install.ps1`.
Upgrade `clumsies` and `clumsiesd` together. Installation preserves credentials,
local Drafts, bindings and caches. Windows packages include the required MSVC
runtime. No Windows/Linux graphical client is provided.

macOS uses the App's resident daemon, Keychain and project bindings. The App
is ad-hoc signed and not notarized; manual installation may require Open Anyway
in System Settings. Windows installers are unsigned. Verify the published
SHA-256 files before installation.

## Changes since v0.20.6

- CLI output defaults to readable text. Lists have aligned headers and local
  timestamps. Project summaries show roles, owners and member counts from a
  batched Server response; `project current` and `project members` provide
  directory-bound context and membership information.
- Lists print directly. Long diffs, plans and Memory bodies use an interactive
  reader; short output, JSON, pipes and redirection bypass it. `--no-pager`
  forces direct output. Server list cursors are followed automatically in
  text mode, independently of the terminal reader.
- `memory list` discovers published paths. `memory show ID_OR_PATH` prints
  only a document's body; `memory show --all` reads all project bodies with
  file separators, including selected organization Memory from one snapshot.
- Draft display paths resolve from ordered operations or their scoped base
  snapshots. Default diffs hide storage/account dumps and show text and
  semantic metadata changes. `--verbose` retains diagnostic evidence.
- Directory context and project selection are clearer. Conflict resolution
  supports explicit text choices, editor input and recovery files, with
  inspected version/reference guards retained.
- macOS/Linux shell installers configure supported bash/zsh startup files.
  macOS CLI links follow the embedded App runtime across upgrades in place.
- Synchronization ignores merged/discarded Drafts when comparing upstream
  resources. An uncached historical base for a terminal Draft no longer
  rolls back installation of a newer snapshot; open/submitted Drafts are
  still checked.

## Compatibility and rollback

Scripts must now explicitly use `--json`; default human text is not a stable
machine protocol. Existing JSON envelopes remain unchanged. New Memory read
commands return a snapshot envelope with `project_id`, `commit_id` and `items`.
The additive project-summary API needs the matching Server deployment; older
Servers remain usable and show unavailable fields as `n/a`.

No database migration is required. Memory reading shows published snapshots,
not unpublished Draft overlays. Complete snapshots download before output,
so memory use grows with project size. Roll back by reinstalling v0.20.6;
existing credentials, bindings and Drafts remain available.
