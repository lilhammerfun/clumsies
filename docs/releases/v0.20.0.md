# Clumsies v0.20.0

This is a normal GitHub release of the current native macOS Clumsies app,
marked **Latest**. It continues the repository's `0.19.x` version history;
`v0.2.0` belongs to the older CLI generation and is not reused.

## Install and update

Download `Clumsies-0.20.0-macos-arm64.dmg`, open it, and drag Clumsies.app into
Applications. Requires macOS 14 or later and Apple Silicon (M1 or newer).
Windows, Linux, and Intel Mac installers are not included in this release.

The app and bundled daemon are **ad-hoc signed and not notarized by Apple**.
GitHub release status is independent of Apple notarization. After first trying
to open the app, use System Settings → Privacy & Security → Open Anyway if you
trust this repository's download. Managed Macs may restrict this exception.
No Xcode, Rust, or other build tools are needed.

Use Settings → General → Check for Updates for signed in-app updates. This
release is also offered to existing Preview installations through their update
feed; after upgrading they follow the regular release channel. Manual upgrades
replace the app in its existing location. Keep the same user data directory:
accounts, local Memory, repository bindings, and settings are retained. Quit
Clumsies before manually replacing it, and avoid keeping two installed copies.

This native app is a different product generation from the old CLI releases;
these instructions do not promise automatic migration of legacy CLI storage.
It connects to `https://app.clumsies.ai` by default and requires an admitted
account. First use downloads the retrieval models.

## Changes since macOS Preview 20

- Browse and manage Memory with a native file tree, explicit directories,
  drag-and-drop, and restored editor tabs. Starter folders follow Project scope.
- Restore independent workspace windows and refresh visible content; improve
  startup window behavior and branding.
- Delete Projects with the associated local history cleanup.
- Sign in with an invited username/password account alongside OIDC, with
  invitation, account linking, and password recovery flows.
- Diagnose requests across the app, daemon, Server, and reverse proxy using
  correlation IDs, structured logs, and bilingual Grafana dashboards.
- Alert on operational failures and failed metric collection. Draft age,
  workflow counts, reconciliation conflicts, and unread records remain useful
  dashboard context without sending misleading backlog emails. Database
  snapshots use gauges and explicit collection freshness.
- Expand bilingual onboarding, deployment, and integration documentation;
  automate Server image delivery with database migration rehearsal, backups,
  health verification, and rollback. Site updates no longer restart Server
  dependencies implicitly.

## Self-hosted deployments

Upgrade Server and native clients together. The current schema includes
explicit directory entries and invited password accounts with nullable email;
older clients may not understand those records. Password login is enabled by
`CLUMSIES_PASSWORD_LOGIN_ENABLED` (default `true`); existing OIDC configuration
is retained. Invitations and password recovery use the configured account
flows, not Alertmanager's SMTP settings.

Server delivery uses an immutable image digest. It rehearses migrations on an
isolated restored database, stops writes, takes a deployment backup, and checks
health after replacing the Server. Reverting only the image is not a complete
downgrade once new-schema data exists: restore the matching pre-upgrade database
backup and image using the documented deployment recovery procedure.

Monitoring runs separately from Server image delivery. Update the collector,
both Grafana dashboards, and Prometheus rules together, preserving SMTP
credentials and monitoring volumes. Email links use localhost ports 9090/9093
through the SSH tunnel. Previously delivered emails keep their old links.

## Build and integrity

The downloadable app uses the existing **Debug ad-hoc runtime contract**, with
the regular App/daemon identities and the stable update feed. It is not a Dev
Instance. The Developer ID / notarized Release build remains a separate workflow;
its signing checks have not been relaxed. A SHA-256 checksum accompanies the
DMG, and Sparkle verifies the signed update archive before installing it.
