# Clumsies v0.20.1

A maintenance release for the native macOS app, bundled daemon, and Server,
with editing, update, Review, Inbox, and observability fixes since v0.20.0.

## Install and update

Download `Clumsies-0.20.1-macos-arm64.dmg`, open it, and drag Clumsies.app into
Applications. Requires macOS 14 or later and Apple Silicon (M1 or newer).
Windows, Linux, and Intel Mac installers are not included.

Existing installations can use Settings → General → Check for Updates.
Signed updates are offered through both the stable and Preview feeds; after
upgrading, the app follows the stable feed. For manual installation, quit
Clumsies before replacing the app and keep the existing user data directory.
Accounts, local Memory, repository bindings, and settings are retained.

This is a normal GitHub release marked Latest. The app and bundled daemon
remain **ad-hoc signed and not notarized by Apple**. After first trying to
open a manual download, use System Settings → Privacy & Security → Open Anyway
if you trust this download. Managed Macs may restrict that exception.

## Changes since v0.20.0

- Preserve Chinese input-method composition while the Markdown editor updates,
  preventing cursor jumps during composition.
- Keep update reminders consistent with Sparkle readiness, including deferred
  installation when quitting. Avoid offering an update action before it is ready.
- Allow compatible agent protocol versions across builds instead of requiring
  identical application builds to connect.
- Restore compact file-tree navigation and add a three-state Inbox select-all
  control after the bulk actions.
- Refresh workspace pages automatically and remove routine refresh buttons and
  the constantly changing footer status.
- Show delta retrieval reuse and the proportion of observed agent runs using
  Memory in Dashboard. These metrics describe captured activity, not unobserved
  agent runs.
- Integrate account security into native Settings navigation and improve account
  audit history and identity preservation.
- Keep rejected Reviews permanently closed. Preserve their proposal content and
  decision while authors edit Drafts and create a new Review through normal
  submission. Remove Resubmit actions and validate historical line comments
  against the frozen content.
- Use standard Prometheus collectors, separate site latency from API latency,
  correlate slow requests, and automate monitoring configuration delivery with
  the required Grafana provisioning directories.

## Server and upgrade notes

Upgrade native clients and Server together for the corrected Review workflow.
Older clients may still show Resubmit; the Server returns a clear error without
reopening history. Normal submission creates a new Review identity.

The Review migration freezes the last available content of existing rejected
Reviews. It cannot reconstruct content already overwritten before the upgrade.
It allows multiple historical Reviews to reference the same Draft while keeping
active submissions serialized. Project publication and independent Organization
contributions retain their existing ownership boundaries.

Back up the database before a self-hosted upgrade and follow the normal immutable
image deployment procedure. Once multiple historical Reviews reference a Draft,
reverting only the Server binary is not a safe downgrade: restore the matching
pre-upgrade database backup and image, or apply a forward fix.

Episode Memory and OpenInference export prototypes are not included in this
release. They remain separately tracked work.

## Build and integrity

The downloadable app uses the existing Debug ad-hoc runtime contract, regular
App/daemon identities, and stable update feed; it is not a Dev Instance.
A SHA-256 checksum accompanies the DMG, and Sparkle verifies its signed update
before installation. Developer ID signing and Apple notarization remain a
separate workflow.
