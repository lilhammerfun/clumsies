# Clumsies v0.20.8

CLI project creation now supplies the required idempotency key. Archived
Commit downloads can read older timestamp metadata on the matching Server
without rewriting historical selection JSON or Blob content.

## Install and update

| Platform | Download | Notes |
| --- | --- | --- |
| macOS | `Clumsies-0.20.8-macos-arm64.dmg` | macOS 14 or later on Apple Silicon. Install the App, then run its Install CLI.command. Existing installations can use Check for Updates. |
| Linux CLI | `clumsies-cli-0.20.8-linux-x86_64.tar.gz` | Extract and run `./install.sh`. Reopen the terminal. Ubuntu 24.04 x86-64 or compatible glibc systems. |
| Windows CLI | `clumsies-cli-0.20.8-windows-x86_64-Setup.exe` | Current-user installation with PATH setup. Reopen the terminal. Windows x64. |

The Windows ZIP supports portable use and includes `install.ps1`. Linux and
Windows packages contain matching CLI and daemon binaries; upgrade them
together. macOS uses the App's resident daemon and Keychain. Installation
preserves credentials, bindings, local Drafts and caches.

Verify the published SHA-256 files before installation. The macOS App is
ad-hoc signed and not notarized; manual installation may require Open Anyway
in System Settings. Windows installers are unsigned.

## Changes since v0.20.7

- `clumsies project create NAME` includes a UUID v4 `Idempotency-Key`, fixing
  the missing-header HTTP 400. Authentication refresh retries reuse that
  invocation's key. Each independent invocation generates a new key.
- Historical Commit downloads accept the older timestamp representation
  during validation while returning the original selection JSON and Blob
  bytes. This requires the corresponding Server deployment; current Memory
  APIs still require RFC3339 timestamps.

## Compatibility and rollback

No database migration or IPC protocol change is required. Existing CLI
commands and JSON envelopes are unchanged. Rerunning project creation is a
new invocation, so it does not deduplicate a prior command with an uncertain
network result. Existing authorization and name-conflict checks still apply.

Restoring the previous CLI restores its missing-key failure against the
current Server; no data restore is needed. The Server compatibility fix does
not rewrite historical objects.
