# Clumsies v0.20.5

The first release with a **Windows and Linux desktop client**, alongside the
macOS app.

## Install and update

| Platform | Download | Notes |
| --- | --- | --- |
| macOS | `Clumsies-0.20.5-macos-arm64.dmg` | Open it and drag Clumsies.app into Applications. Requires macOS 14 or later and Apple Silicon (M1 or newer). |
| Linux | `Clumsies-0.20.5-linux-x86_64.tar.gz` | Unpack, then `./clumsies-desktop`, or `./install.sh` to put it in your launcher. x86-64, glibc. |
| Windows | `Clumsies-0.20.5-windows-x86_64-Setup.exe` | Run the installer, then open Clumsies from the Start menu. Installs for the current user without administrator permission. Windows 10 or later, x86-64. |

The Windows ZIP remains available as a portable alternative. The installer adds
an optional desktop shortcut and a Windows Settings → Apps uninstall entry.
Close the client and active Agent sessions before updating or uninstalling;
the installer stops its own engine and preserves account and Memory data.

Each package carries the client and the engine it starts (`clumsiesd`), a
README, and a SHA-256 checksum. The desktop packages are not signed: Windows may
show a SmartScreen warning the first time ("More info" → "Run anyway"), and the
macOS app is ad-hoc signed and not notarized by Apple, so a manual download may
need System Settings → Privacy & Security → Open Anyway.

## Changes since v0.20.4

### Desktop client (Windows and Linux)

The client is built on GPUI, the framework Zed uses, and shares the daemon, the
Server API, and the macOS client's information architecture:

- **Sign in** with a Server address and the browser, or with a local password
  when the deployment has passwords enabled; an invitation and a password reset
  use the same form, and a Server that has never been configured is set up from
  it.
- **Memory**: Projects as a tree of documents, tabs, an editor that stores
  drafts through the daemon, a diff against what is published, and the commands
  a document, a folder or a selection take — including one Review naming every
  open draft.
- **Memory spaces**: create one from the Project filter, name it, describe it,
  connect the folders on this machine that belong to it, and read the
  Organization's own Memory beside it.
- **Reviews**: the queue with its status and coordination, and the open Review as
  a navigator of changed documents beside a unified diff, with the decision and
  the merge.
- **Dashboard**: the macOS page — daily closing inventory, retrieval outcomes,
  delta reuse, agent usage, directory coverage and the most retrieved documents —
  read from the Server's statistics and the engine's local telemetry.
- **Settings**: the account and what it signs in with (local password, identity
  provider), the Agent integrations this machine has installed, and support
  information.

Initial desktop release limitations:

- Windows builds, credential-vault and named-pipe tests, and daemon startup are
  checked in CI; the Windows GUI has not been tested on a physical desktop.
- Windows managed Agent integration currently supports Codex only and requires
  its CLI on PATH. Other Windows integrations are deferred.
- Inbox, Bundles and Activity, and Review comments and resubmission, are deferred.
  Create a Project, edit Memory, connect a work folder and use MCP, and submit
  and merge a Memory Review are the supported first-release paths.
- The Project creation dialog asks for a name and description. Link repositories
  afterwards in Project settings; selecting a Bundle during creation is deferred.
- Saving failures keep edits open and prevent closing the window or tabs,
  signing out, or leaving the Project. Retry the action after the engine recovers.

`apps/desktop/README.md` says how to build and run it; `DESIGN.md` and
`COMPONENTS.md` record the rules it follows and where it deliberately differs
from macOS (window controls at the right, commands in each pane's header, this
platform's keys).

### Server, daemon and macOS app

- Check AI tool integrations once per installed daemon build instead of on every
  launch, and skip tools with nothing installed.
- Rejected reviews stay closed, and their history is preserved.
- Review file paths are resolved before the merged tree is drawn.
- Inbox receipts are allowed for draft conflicts the account can reach.

## Compatibility and rollback

No API, schema, or data migration is required. The desktop client shares the
daemon and Server APIs with the macOS app and stores its own navigation state
under the user's state directory. To roll back, install the v0.20.4 macOS app or
the previous desktop package; no database restore is needed.

## Build and integrity

Each package ships with a SHA-256 checksum, and the release is assembled from the
same scripts the branch's CI runs before any tag exists
(`apps/desktop/packaging/assemble-linux.sh`, `assemble-windows.ps1`). The macOS
app uses the existing ad-hoc runtime contract and stable update feed, and Sparkle
verifies the signed update before installation.
