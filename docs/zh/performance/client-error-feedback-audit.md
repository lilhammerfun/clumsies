# macOS 错误反馈审计与修复

审计日期：2026-09-21。基线：`940d5830`。实现分支：
`codex/macos-error-feedback`。本报告描述工作区中的修复，
不代表已经发布。

## 结论与范围

检查覆盖 `apps/macos/Sources` 的全部 127 个 Swift 文件，
包括 App 生命周期、Server/XPC 边界，以及 Inbox、Memory、
Reviews、Bundles、Dashboard、Activity、项目、组织管理、
设置和诊断界面。搜索结果中的引用数量不等于缺陷数量。

三个缺陷互相叠加：请求边界把传输细节变成界面文案；不同归属方各自报告同一次失败；
加载状态没有区分首次失败、刷新失败和用户操作失败。删掉所有错误会隐藏重要结果；
只改写文案也无法消除重复呈现。

## 已修复的问题

| 范围 | 修复后的行为 |
|---|---|---|
| Server、XPC、认证与启动 | 先分类失败再呈现；wire 正文、请求 ID、解码路径和进程退出码不进入普通界面。本地编写的校验与恢复指引仍然有用。 |
| 主窗口与设置窗口 | 每个窗口只保留一条可关闭的服务状态。忽略已取消和已被取代的请求；权限重置时清空账号范围内的状态。 |
| Workspace 刷新 | 临时服务故障保留本来已经可用的窗口；冷启动失败仍给出恢复入口；旧账号的失败不能改变新工作区。 |
| Inbox 阅读 | 欢迎正文通过原生导航打开。消息页面没有阅读 sheet、重复的回执错误或列表筛选。 |
| Inbox 回执 | 先持久化已读/归档意图再更新界面，并沿用现有刷新周期重试。保留权限与通知版本边界，合并相反意图，永久失败则回滚。在途读取不会禁用归档或之后的未读意图。 |
| Inbox 加载 | 首次加载失败显示恢复入口，而不是空 Inbox。刷新保留通知。本机状态探测失败不会制造一条业务通知。 |
| Reviews 与 reconciliation | 去掉重复的加载反馈和嵌套错误 alert。提交失败时在当前任务中保留输入和冲突处理选项。 |
| Memory 与集合 | 后台服务失败不再同时变成“操作失败”横幅。保留内容；保留必要的保存、部分完成、冲突和数据丢失反馈。 |
| Dashboard 与 Activity | 刷新失败后保留内容；首次加载与分页恢复保持区别。 |
| 项目与管理 | 只在同一项目和同一权限内保留仓库绑定。统一存储错误，去掉重复的管理横幅，保留缓存写入限制和分页恢复。 |
| 检索历史 | 保留已加载的历史和详情；区分首次加载失败与没有记录。分页恢复放在窗口角落，选择变化时清空过期详情。 |
| 取消与导出 | 识别 task、URL 和 Cocoa 取消。提供可操作的磁盘空间和文件访问文案。导出诊断保留在日志中。 |

## 提示位置与语义复查

网络横条只是其中一处。复查还处理了 Inbox 回执错误、
Memory / Bundles / Reviews 刷新条、工作区底部错误条、
Activity 分页错误、组织管理缓存和操作提示、项目表单错误区、诊断导出和分页错误。

反馈分成两类，不能把所有错误放进同一种浮层：

- 窗口级连接／缓存状态：右下角的图标和文字，使用次要文字色；没有背景框、圆角、
  阴影或自动消失计时器，不占据侧栏和正文布局。`pageFeedback` /
  `feedbackHost` 仍保证每个窗口只展示一条非表单反馈，重复来源一起关闭。
  显式操作失败用错误色，连接状态保持低强调。
- 表单内保存／提交失败：项目创建和编辑、组织名称和域名、组织和项目成员、Review 提交、
  Draft reconciliation、登录设置，均在当前表单内显示红色错误文字加图标。
  保留输入和原生操作按钮，重试时清理旧错误；不再在表单上叠加卡片。
  只在明确识别字段错误时指向相应字段，未知 HTTP 400 不能当作某个字段有错。

ServerClient 的写请求失败仍抛给调用方，但不再同时生成窗口级服务提示；
GET / HEAD 的读取和刷新失败维护连接状态，避免保存失败在弹窗内外重复出现。

设置侧栏图标跟随正文大小，占位与主窗口一样为 16 × 16 pt，在连接和认证失败时也不变。
真正的首次加载失败、无权限或对象不可用状态仍属于内容本身；字段校验、删除确认、
未保存编辑保护和历史诊断记录保留。

颜色不能是错误的唯一表达，因此红色同时配有错误文案和图标。
[Apple：Differentiate Without Color Alone](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/differentiate-without-color-alone-evaluation-criteria)

## 统一处理规则

| 场景 | 展示与恢复策略 |
|---|---|
| 后台刷新遇到断网、超时、500/503、本地服务不可用 | 保留内容，窗口级服务状态；不弹窗，不创建 Inbox 通知 |
| 首次加载失败、没有可用内容 | 在内容区域显示“无法加载”及重试入口，不能伪装成空列表 |
| 用户主动保存、提交、删除失败 | 明确说明操作没有完成，保留输入与当前任务；不自动重复有副作用的请求 |
| 400/422 | 保留本地输入校验；未知服务端拒绝使用简明提示，不直接显示响应正文 |
| 401 | 提示重新登录；不自动注销或抛弃正在编辑的内容 |
| 403 | 提示访问权限发生变化，并指引刷新检查 |
| 404/410 | 表达对象已不可用；不当成断网，不据此制造成功结果 |
| 409/412 | 提示查看最新版本，沿用已有 reconciliation 流程 |
| 429 | 提示稍后重试，不增加高频重试定时器 |
| 请求取消或过期响应 | 不展示错误，不允许旧请求覆盖新页面或新账号 |
| 可恢复的已读/归档请求失败 | 保存在账号、组织和服务器隔离的本机队列，恢复后同步；新版本消息仍未读 |

请求 ID、原始错误和解码细节不属于普通业务界面。Activity 中用户主动展开的技术详情、
检索诊断记录及隐私过滤后的日志是诊断入口，仍可提供技术证据。删除确认、
放弃未保存编辑等需要用户决策的提示保留。导出失败和重启失败改为右下角反馈，不再弹出模态错误框。

## 依据与取舍

Apple HIG 建议谨慎使用 alert，并以 Mail 的连接状态为例：
连接不可用可以用非打断式状态表达，启动离线时也可以展示缓存内容。
[Apple HIG — Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)

欢迎消息没有要求用户立即决定的任务，因此使用常规导航阅读。HIG 要求模态展示有明确收益，
并指出它会打断原有上下文。
[Apple HIG — Modality](https://developer.apple.com/design/human-interface-guidelines/modality)

NN/G 强调按影响程度选择反馈、提供恢复建议、保留输入，并将技术代码留给诊断用途。
它也支持在真正需要修正输入时就近提示，因此本次没有把所有错误都一律隐藏。
[NN/G — Error-Message Guidelines](https://www.nngroup.com/articles/error-message-guidelines/)

窗口级状态、待同步通知回执和页面状态的具体组合是本项目的实现选择，
并非 Apple 指定的一套固定组件。实现沿用原生 NavigationStack、
现有 toolbar、日志和 30 秒数据刷新周期，没有引入通知框架或通用写请求重试器。

## 重复实机故障测试

在当前 worktree 启动 `just dev-macos`，进入 Inbox，
等待通知加载。以下命令每次执行一个，默认 60 秒后自动恢复，也可按 Ctrl-C 提前恢复：

```sh
just dev-macos-fault offline
just dev-macos-fault 500
just dev-macos-fault 400
just dev-macos-fault 404
```

`offline` 时，刷新后继续阅读欢迎正文、标记已读或归档；确认内容保留、本机状态立即变化，
并在恢复后检查服务端回执。`500` 时刷新，确认只有一条服务状态提示且内容保留；
daemon 的缓存回退会把失败表述为暂时无法连接，而不是暴露 HTTP 细节。
`400` 和 `404` 时先选中一条通知并显式标为未读，确认就近反馈与回滚，
而不只是后台刷新行为。

工具只接受当前 worktree 的 loopback Local Instance，
复用实例身份校验及生命周期锁；暂时停止它的 Server，构造真实 HTTP 失败，
退出时恢复原 Server 并核对健康状态。App、daemon 和数据库保持运行；
没有添加产品内的调试入口。技术错误体包含专用标记，
验收确认该标记和请求 ID 没有出现在普通界面。

欢迎消息创建逻辑通过独立 PostgreSQL 测试验证：新用户首次签发会话时生成一次，
正文存在，再次登录不会重发，已读和归档仍保留。实机截图复用 Dev 用户原有欢迎消息，
通过正常回执 API 恢复可见和未读状态，不伪造第二次首次登录。
