# 服务端热路径与 Rust 架构

Review 与 Commit 列表曾经很慢，因为列表请求会水合它们根本不会返回的载荷。
即使查询本身正确，也会成倍放大数据库、分配与解码工作。

## 设计

列表查询现在只选取列表形状的行并直接构造摘要。详情路由保留完整水合。
Commit 元数据读取与载荷读取彼此分开，因此列表不会意外依赖体积庞大的不可变正文。
这去掉了加索引也无法去掉的工作。

Server 仍然是按限界上下文组织的模块化单体。HTTP 解析、应用服务、
领域模型与 PostgreSQL 访问各自负责；对性能敏感的读取留在各自所属的上下文内。

## 验证与债务

测试使用真实 PostgreSQL 与应用路由。热路径检查以结构性方式阻止载荷依赖，
而不是依赖脆弱的耗时阈值。生产对比使用相同的路由与请求体，并把上游时间与传输时间分开。

共享的仓库门面仍然暴露宽泛的跨上下文能力。只在具体改动触及该边界时才收窄它。
