# macOS 首次就绪与 daemon 同步

`first-ready` 指的是所选 Project 能呈现可用的权威视图。
它不表示每个 Draft、Issue、Review、缓存写入与投影都已结算。

## 关键路径拆分

旧路径把「完整」当作「可用」，并被跨区 RTT 放大了串行工作。
当前路径在首次就绪之前只保留身份、选择与最小权威状态；相互独立的数据集在之后加载。

每个后台结果都携带发起它的 Workspace generation。
权威或会话变化会让过期工作失效。延迟到达的记录按条合并，而不是整体替换更新的集合。

## 同步

Project Commit State 使用有界并发。
Draft 投影会对 base Commit 的加载去重。投影更新与游标推进是原子的。
GET 缓存持久化使用有界合并写入器，而 401
刷新在发布凭据或缓存状态之前会再次比对会话快照。

首次就绪与后台结算的测量保持分开。带日期的结果与未完成项见
[验证证据台账](/zh/performance/evidence-ledger)。
