# 端到端延迟模型与诊断

性能工作从定义「完成」开始：首次可用界面、完整响应、后台结算，还是持续吞吐。
这些指标不能互相替代。

## 关键路径

端到端延迟包含必需的 DNS、连接与 TLS 建连、往返、Server 工作、传输、解码、
持久化与界面发布。并行工作贡献的是它最长的一条必需分支，而不是所有分支之和。

记录百分位时要带上样本数。把 TTFB 与完整响应时间分开，把线上字节与解码后大小分开。
用共享的操作身份把客户端、代理、Server、数据库、daemon 与界面串起来。

## 优化顺序

1. 去掉关键路径上不必要的工作。
2. 把非必需工作移到完成之后。
3. 成批处理跨边界调用，并给独立并发设上限。
4. 复用会话与连接。
5. 减少线上字节与响应后的工作。

先定义事件与环境，采集基线，定位主导边界，只改一个有因果关系的变量，然后重复，
最后补上最小的结构性回归检查。参见
[Server](/zh/performance/server-hot-path)、
[macOS](/zh/performance/macos-first-ready) 与
[gzip](/zh/performance/gzip-experiment) 的案例。
