# 端到端延迟证据台账

这是性能证据的带日期索引。一个数字只有连同 revision、环境、路由、输入、
样本数与完成定义才有意义。

## 证据分组

- Server 热路径对比在列表形状读取前后使用完全相同的列表路由。
- macOS 证据把首次就绪与后台结算分开。
- gzip 证据对比上游时间、端到端时间、编码与线上大小。
- 无变化同步验证空闲轮次避免不必要的载荷与持久化工作。

对于「列表不水合载荷」这类性质，结构性测试是最强的保障。重复的生产样本体现运行影响；
一次性的本地计时只用于诊断。

适用的验证包括 Rust 测试与 lint、macOS 契约、API 兼容性、
VitePress 构建、内部链接与签名检查。生产证据把已部署的 revision
与本地构建分开标识。带日期的详细测量与 trace
链接保留在仓库的历史中文稿中（
`docs/zh/archive/performance/evidence-ledger.md`）。
