# Inbox

Inbox 是 macOS 侧栏中的个人通知入口。它横跨可访问的 project，
提供 Inbox、未读与已归档过滤、消息类型过滤与搜索。类型包括 Review 请求、
Review 评论、Review 结果、远端更新、同步错误、欢迎与访问变更。
Project 仍然是消息上的来源标签。归档只隐藏当前显示的 revision；
之后的新事件会让该主题重新以未读出现。读取与归档都不改变 Review 或 Memory。

列表在主导航工具栏中复用 `ToolbarFilterMenu` 处理状态与消息类型。
已读/未读、归档/恢复与刷新位于尾侧，最右侧是共享的 `ClassicSearchField`，
遵循工作区的 macOS 14/26 摆放规则。⌘K 聚焦搜索并保留过滤条件。

每行有两行文本：标题与绝对时间戳，随后是事件摘要、来源与一个具名操作。文本超出时截断，
而不是增加第三行；tooltip 展示完整摘要。通知按最新在前排序。未读消息使用圆点、
更粗的标题与无障碍标签。没有逐行归档图标、通用展开箭头或行内展开。

点击或选中单条通知会把它标为已读，但不进行跳转。在未读过滤下，
被选中的行在选中项改变之前保持可见，因此它的操作始终可用。
显式 Mark as Unread 在该行保持选中期间仍然有效。
原生范围选择与多选会为批量工具栏与右键菜单命令保留未读状态。
**Mark as Read / Unread**（⇧⌘U）只改变已读状态。
**Archive**（⌃⌘A）隐藏当前显示的 revision，但不标记为已读；
**Move to Inbox** 恢复它并保留其已读状态。
归档与恢复会为成功的条目注册原生 Undo 操作。部分失败会停止整批操作，
让失败条目保持可见并显示错误。Undo 不能跨越账号变更，
也不能覆盖更新的通知 revision。

这些选择遵循
[Apple Mail](https://support.apple.com/en-in/guide/mail/mlhlp1052/mac)
的选择与命令模式，以及 HIG 关于
[上下文菜单](https://developer.apple.com/design/human-interface-guidelines/context-menus)
与
[工具栏](https://developer.apple.com/design/human-interface-guidelines/toolbars)
的指南。下文中确切的通知识别与已读时机属于 Clumsies 的产品决定。

| 消息 | 显式操作与目标 | 已读行为 |
| --- | --- | --- |
| 欢迎 | **Read Message** 在原生 sheet 中打开其原始 Markdown 正文。当用户有可访问的 project 时，**Open Memory** 可用。 | 单选或消息被展示时标为已读。 |
| 被加入 project 或角色变更 | **Open Project** 打开该 project 现有的 Memory 工作区，访问权限仍然有效。 | 单选或成功跳转时标为已读。 |
| 被移出 project 或组织角色变更 | 在行内说明变更，不提供详情页或不可访问的目标。 | 单选时标为已读，或使用 Mark as Read。 |
| Review 请求、评论或结果 | **Open Review** 打开既有的 Review 页面。 | 单选或成功跳转时标为已读。 |
| 远端更新 | **Open Memory** 切换到对应 project，并在既有的 Diff 标签页中打开有远端改动的文件。如果这些改动已经同步，则只打开该 project 的 Memory 工作区。 | 单选或成功跳转时标为已读。 |
| 同步问题 | **Retry Sync** 直接执行恢复；不存在虚构的消息详情页。 | 单选或恢复成功时标为已读；已解决的本地问题会消失。 |
| 没有目标的信息 | 没有打开按钮，也没有双击跳转。该行仍可选中以执行已读/归档命令。 | 单选时标为已读，或使用 Mark as Read。 |

只有欢迎消息有原始正文与自己的阅读视图。Review、远端更新与访问类通知复用既有目标，
或保持为信息行；同步错误直接执行恢复。跳转错误会留在列表中；选中本身可能已经确认了该通知。
打开 Memory 只展示它已有的对比；读取、归档或撤销永不发布、丢弃、合并或解决任何文件。

## 通知来源

| 来源 | 接收者与分组 | 目标 |
| --- | --- | --- |
| 首次成功登录 | 每个用户一条欢迎，随首个会话持久化；不跨设备或后续登录重复，也不为已有会话的既有用户补发 | 原始欢迎正文 |
| 被加入或移出某个 project | 受影响的成员，排除自己的操作；每次实际变更一条 | 仍可访问时指向该 project 已有的 Memory；移除仅为信息 |
| Project 或组织角色变更 | 受影响的成员；包含前后角色与操作者，并标明作用域；角色未变则不发通知 | 适用且可访问时指向该 project 已有的 Memory |
| Review 已提交或重新提交 | 活跃的 owner/admin project 成员，排除操作者；每个 Review 一条 | Review 详情 |
| Review 评论 | 作者、参与者，以及仍然保有成员身份的既有接收者，排除操作者 | Review 详情 |
| Review 通过、拒绝或合并 | 作者、参与者，以及仍然保有成员身份的既有接收者，排除操作者 | Review 详情 |
| 远端 Memory 发布 | 受影响 project 的成员，排除操作者；每个 project 一条 | 既有 Memory 工作区与文档 Diff 标签页 |
| 同步失败或本地服务不可用 | 本机；每种状况一条 | Retry Sync |

普通的 Draft 创建、编辑、重命名、删除、上传与提交状态都不是通知来源。
Inbox 不获取也不汇总 Draft 清单，没有 Drafts 过滤器或 Memory
Changes 页面。文件颜色与既有的 Memory/Review 命令继续表达用户自己的工作。

远端更新在 Project 发布之后，或在 Org 发布影响到某个 project 选中的
Memory 之后发出。冲突通知发给 Draft 作者；干净的同步不需要确认。
Server 通过资源选择找到这些 project，并投递给它们的活跃成员，排除发布者。
仅仅推进一个无关的 organization Ref、保存 Draft，
或属于某个使用其他 Memory 的 project，都不会触发远端更新通知。
重命名与删除影响发布之前引用该资源的 project；
新发布的文件在进入 project 的选择之后通知发起发布的 project。

没有对应 Server 通知的已知远端改动，仍可从既有的按资源同步计划中发现。
Sync Errors 覆盖上传或下载失败、同步降级，以及本地同步服务不可用。
仅有待上传内容或普通 Draft 编辑不符合条件。已解决的本地同步问题会消失。

文件树保留文件类型图标、右键菜单与变更颜色：新增为绿色、修改为琥珀色、删除为红色，
已提交但尚未合并的改动同样如此。尾部的状态图标已移除。Review、
更新与对账命令仍在既有的文档与文件菜单中；文档没有额外的状态条。
工作区工具栏中的后台通知图标已移除。操作失败（包括保存失败）仍停留在发生操作的位置。

## 持久化与访问

Server 在产生事件的业务事务中存储欢迎、访问变更、Review 与发布通知。
既有的开放 Review 会为符合条件的审阅者回填。读取与回执更新会重新核查接收者与组织。
Review 与远端更新的内容还要求当前仍是 project 成员。
个人访问通知在被移除或 project 被删除之后只保留事件数据与 project 名称快照；
这不会授予对该 project 或其内容的访问权。当 project 列表变化时，
客户端也会移除不可访问的来源通知与 project 操作。直接合并只产生一条合并结果；
不成功的写入不产生通知。

`GET /api/v1/me/inbox` 返回包含已归档/已读主题的 keyset 分页。
`PATCH /api/v1/me/inbox/{notification_id}`
接受当前显示的 `version` 以及 `read`、`unread`、
`archive` 或 `restore`。过期的回执不能确认更新的 revision，
也不能撤销更新的归档/已读状态。已读状态与归档状态彼此独立。
线上字段见公开的 OpenAPI 契约。

本地回执使用按 server、organization 与 user 划分的偏好设置。
权威变化会清除可见状态并让进行中的请求失效。跨 project
跳转会在切换之前冲刷待保存的编辑；远端更新会先下载当前 commit，再比较文件。

当管理员添加成员时，project 成员身份目前立即生效。通知说明该用户已被加入；
它不为一个并不存在的邀请流程提供接受或拒绝。组织账号被停用会撤销登录，
因此 Inbox 不是停用账号的投递通道。

## 首版限制

- 刷新使用既有的 30 秒工作区节奏加显式刷新。这一版没有系统推送通知。
- Server 通知使用 daemon 既有的离线响应缓存。
  已读/归档写入需要连接并会上报失败；它们不会离线排队。本地回执在离线时仍可使用。
- 本地同步错误与远端更新兜底回执不跨设备同步。
- 通知历史按主题聚合并加载全部页面。它不是审计日志。评论会打开其 Review，
  但不会滚动到某条评论。

`InboxTests` 覆盖回执持久化、revision 竞争、权威失效、
离线错误与既有远端改动。`inbox_flow` 在隔离的 PostgreSQL 上演练
HTTP API，包括提交/评论/拒绝/重新提交/合并的生命周期、远端发布、
按选择作用域投递的更新/重命名/删除、分页、过期回执、被撤销的访问、跨登录的欢迎去重、
未变更角色，以及个人通知在被移除与 project 删除后仍然保留。
